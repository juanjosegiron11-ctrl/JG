PROYECTO MELODÍAS CON INICIO DE SESIÓN

ARCHIVOS
- index.html: formulario de inicio de sesión con los campos usuario y contraseña.
- melodias.html: página original de Melodías.
- login.js: llama a la función segura de Supabase.
- auth-guard.js: exige iniciar sesión en este navegador y permite cerrar sesión.
- supabase-config.js: URL y clave publicable del proyecto.
- supabase/functions/validar-login/index.ts: función que consulta usuariosAunar en el servidor.

IMPORTANTE: falta desplegar la Edge Function en el proyecto del profesor.
Con solo la URL y la clave publicable no se puede desplegar ni configurar una función.
El propietario/administrador del proyecto debe hacerlo o autorizarte.

PASOS PARA EL PROFESOR / ADMINISTRADOR
1. Confirmar que la tabla se llama exactamente usuariosAunar y que las columnas son usuario y contrasena. El campo usuario se compara tal como está guardado en la tabla.
2. En Supabase, crear/desplegar la Edge Function llamada validar-login usando el archivo:
   supabase/functions/validar-login/index.ts
3. Configurar los secretos de la función en el proyecto:
   SUPABASE_URL = URL del proyecto
   SUPABASE_SERVICE_ROLE_KEY = clave secreta service_role del proyecto
   La clave service_role NUNCA debe copiarse en archivos HTML o JavaScript del navegador.
4. Desplegar la función con Supabase CLI desde la carpeta del proyecto:
   supabase functions deploy validar-login --no-verify-jwt
5. Probar con una cuenta de prueba autorizada.

SEGURIDAD Y LIMITACIONES
- Este código no descarga ni devuelve contraseñas al navegador.
- La tabla de la captura parece almacenar contraseñas en texto legible. Eso no es seguro; el administrador debe migrar las cuentas a Supabase Auth y cambiar las contraseñas expuestas.
- La función usa la tabla existente solo como puente temporal para el ejercicio. Debe añadirse limitación de intentos (rate limiting) y, preferiblemente, migrarse a Supabase Auth.
- GitHub Pages sirve archivos estáticos. El control de sesión del navegador evita la navegación accidental, pero NO protege el HTML frente a alguien que conozca la URL directa o manipule el navegador. Para proteger contenido realmente privado se necesita un backend que controle también el contenido.
- La clave publicable puede estar en el navegador; nunca incluir service_role.
